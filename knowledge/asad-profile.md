# Engineering and Problem-Solving Examples

## Production Debugging

When functionality unexpectedly fails in production, Asad's general approach
is to narrow down the problem systematically.

Depending on the issue, this can include:

1. Checking console errors, logs and API requests.
2. Reviewing the affected functionality.
3. Reproducing and analyzing the problem.
4. Isolating or disabling sub-features step by step when useful.
5. Identifying the specific source of the issue.
6. Implementing the fix.
7. Preparing a new pull request.

Production problems are treated as high priority.

## Dynamic Chart Legend Problem

Asad worked with a Vue chart component capable of displaying different chart
types such as line, bar and pie charts.

The number of legends was dynamic and could cause content to overflow the
available container.

The layout also needed to maintain appropriate space for both the graph and
its legends.

Because the charts came from a third-party library, direct customization was
limited.

Asad implemented logic that considered the chart type and number of legends.

The available chart height was adjusted when necessary, and when the legend
count became too large, additional information could be presented through a
tooltip.

This allowed the visualization to remain usable within the available layout.

## Working With Existing Code

When Asad inherits unfamiliar code, he first tries to understand how the
functionality behaves and how the main functions and processes are connected.

He uses the running application, browser inspection and local experimentation
to understand how changes affect the system before making larger
modifications.
